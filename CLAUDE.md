## Architecture
- Main container: `components/GamificationPlatform.jsx` (~1500 lines, single client component; the old pre-v2 shell was excised 2026-07-15)
- **`parked/`** — predictions, trivia, and quests were REMOVED from the platform 2026-07-15 (the pre-casino missions and the streak bonuses followed 2026-10-07); all their code lives in `parked/` (mirror structure + README with restore notes). Nothing in `parked/` is compiled. Don't re-import from it — `git mv` files back to restore
- `components/games/` — 9 live games, all `stakeOnly` (no free plays; every round is staked inside the game via `onSpend`, `DEFAULT_DAILY_PLAYS` = 0 for each): **Njuka Boss** (card game vs fair bots, own STAKES 1/10/25/50, no house edge so no RTP knob) plus 8 **candy games** — Coin Flip (`coinflip`), Penalty Crash (`penalty`), Chicken Catch (`chicken`, farmer chase; scene pieces in `chicken/shared/`), **Chicken Catch 2** (`chicken2`, a crash game: golden eggs push the multiplier up, cash out before the farmer falls, 10× cap, engine `lib/chicken2/crash.mjs`, crash point drawn per stake so every cash-out returns exactly the RTP after rounding), Lucky Minibus (`minibus`), Bottle Spin (`bottle`), Scratch Card (`scratch`, image key `luckyScratch`), Lucky Numbers (`numbers`). Stakes **1/5/10/20** for `numbers` and `chicken2` (default chip 5); the rest **1/10/25/50** (default chip 10); a remembered stake no longer offered falls back to the default chip; card footers read `stakeRange` '1–20' / '1–50'. Each candy game = `components/games/<id>/` + pure engine in `lib/<id>/` + `tests/<id>-*.test.mjs` + card art `public/games/<id>/card.svg`; wiring = an overlay block in `GamificationPlatform.jsx` + entries in `MINIGAMES`, `DEFAULT_DAILY_PLAYS`, `images.js`, `tutorials.js`. The pre-2026-09 games (Dice, HighLow, Plinko, old Scratch, StopClock, TapFrenzy, Wheel) are parked in `parked/`
- **Deploys on push**: every push to `main` auto-deploys via the Vercel GitHub integration (no `vercel` CLI needed); watch it with `gh api repos/crmbwanabet/gamification-platform/commits/<sha>/status --jq .state`
- **Candy kit** (`components/games/candy/`): `CandyScreen`/`CandyButton`/`CandyChip`/`tokens` give every candy game the same shell; `WinCelebration` is the single win moment (YOU WON panel, count-up, COLLECT flies coins into the balance pill; its effects are StrictMode-safe, so it works under `next dev` too). The platform credits the payout via `onRound` before the panel; result lines read plain WIN / LOSE and there are no in-scene "+N" floats
- **`lib/pick6/engine.mjs`**: shared pick-one-of-6 engine (win chance = rtp × stake / rounded payout, top payout 50 × 4x = 200) behind Penalty Crash, Chicken Catch and Lucky Minibus; outcomes come from `crypto.getRandomValues` (tests pin it via an injected rng)
- **RTP + rounding (`lib/rtp.mjs`, 2026-10-07)**: every candy game has a per-game RTP in remote config, **`games.<id>.rtp`**, default **0.98**, clamped to **[0.97, 0.99]** (`clampRtp`; `merge.mjs` applies the same clamp; `/api/admin/catalog` lists `{ default, min, max }` per game); `GamificationPlatform` passes `rtp={cfg.games.<id>?.rtp}` into each game → engine. Every payout = `stake × mult` rounded **half up** in integer hundredths (`roundHalfUp`, no float traps). Each engine derives its odds from the ACTUAL rounded payout at the chosen stake so the RTP holds at every stake: pick6 + Coin Flip `P(win) = rtp × stake / payout`; Bottle Spin solves the TRY AGAIN weight per stake; Scratch rescales its ladder per stake; Lucky Numbers picks a small whole-coin paytable per stake (achieved 97.0–99.0%, stake 1 fixed at 98.97%); Chicken Catch 2 uses `P(C ≥ x) = rtp × stake / payout(stake, x)`. `tests/rtp-all-games.test.mjs` checks every game × stake exactly
- **Economy** (`GAME_ECONOMY` in `lib/data/platform.js`): max win per game = 200 coins, extra play = 50 coins (a deliberate gamble). All pay tables scaled to the cap. NOTE: `extraPlayCost` is remote-config-driven; `maxWin` is NOT wired into pay tables yet (dashboard shows it read-only)
- **Remote config** (admin dashboard backbone, 2026-07-15): Supabase tables `platform_config`/`store_items`/`activity_events`/`purchases`/`casino_activity` (service-role only). Public `GET /api/config` (60s edge cache) merges rows over `lib/config/defaults.js` via tested `lib/config/merge.mjs`; `useRemoteConfig()` hook feeds `GamificationPlatform` — economy (`coinsPerKwacha`, `gemValues`), game visibility, daily plays (`lib/config/plays.mjs`), extra-play cost, store items, mission overrides (`lib/config/missions.mjs`, keyed by the casino mission ids), daily/level reward tables (`streak_rewards` rows are ignored since 2026-10-07; `streakRewards` default = `[]`). Config failure ⇒ hardcoded defaults, players never blocked. Changes land next widget load. `POST /api/track` = batched activity beacon (`lib/track.js`): session_start/game_played/mission_completed/daily_claimed/level_up. Tests: `npm test` (node --test, pure .mjs modules)
- Game rewards are COINS displayed as number + `/ui/reward/coins.png` icon (never "K"-money labels on rewards; K amounts appear only for redemptions/wallet value). Rewards read "{N} coins" ("5,000 coins", "1 emerald", "2 rubies", "1 diamond", "30 XP"), never a bare number: use `amountText`/`rewardParts` from `lib/rewardText.mjs` (thousands grouped), and `CurrencyAmounts` (icon + words) from `RedesignShell` for reward rows
- **Gem economy (2026-10-07, `lib/economy/currency.mjs`)**: **1,000 coins = K1** (remote config `economy.coinsPerKwacha`, default 1000, positive integer ≤ 1,000,000, validated in `merge.mjs` via `cleanEconomyRow`). Three **prize gems** replace the old gems/diamonds, valued in coins by `economy.gemValues` = `{ emerald: 5000, ruby: 10000, diamond: 20000 }` (K5 / K10 / K20; kwacha value derives from coinsPerKwacha). **Gems are WON AS PRIZES ONLY**: nothing sells them, coins never convert into them, and **no default source pays them today** — the dashboard attaches gem prizes through `mission_overrides` rewards (`{ "casino_legend": { "reward": { "emeralds": 1 } } }`; 0 removes a currency), the `level_rewards` row, or `daily_rewards`; every reward path (mission/level/daily claims, `triggerReward` floats + fly-to-header targets `.currency-emerald-target`/`-ruby-`/`-diamond-`, notifications, level-up modal) handles `emeralds`/`rubies`/`diamonds`. State keys: `kwacha` (coins, legacy name), `emeralds`, `rubies`, `diamonds` (**key reused**) + marker `currencyVersion: 2`; the retired `gems` is held at 0. A blob WITHOUT the marker is pre-reset: its gems/diamonds count as 0 in client hydration (`migrateCurrencyState`), `/api/state` (also mirrors columns `emeralds`/`rubies`/`diamonds`, no longer `gems`) and the `purchase_item` RPC — an old test balance can never become a K20 diamond. `cleanReward` drops `gems`/junk from any reward row. Header = wallet pill (coins + 3 SVG gems from `public/ui/gems/`), tap → `WalletSheet` ("1 Emerald · worth K5", total value). Spec: `docs/superpowers/specs/2026-10-07-gem-currencies-design.md`
- **Daily login reward** (`lib/data/dailyRewards.mjs`, re-exported by `platform.js`, remote-config key `daily_rewards`): days 1–6 = 10 coins, day 7 (7 in a row; a missed day resets to day 1) = 100 coins, coins only, so a full week = **160 coins**. Streak BONUSES were removed 2026-10-07 (`STREAK_REWARDS` parked in `parked/lib/data/streakRewards.legacy.js`); the streak counter still drives day 1→7. **Logged in = daily reward ready**: only a resolved bwanabet SSO session (`session.status === 'ready'`) can claim; anonymous visitors see "Log in on bwanabet.com to claim" and no Home badge
- Daily plays: all game plays refresh to their allowance at 6am local (`refreshDailyPlays` — top-up, extras carry over); `playGame` charges the extra-play cost when free plays run out
- **Widget mode**: the platform embeds on bwanabet.com as a full-screen popup — `public/widget.js` launcher (red-X dismissable bubble) + iframe (`?widget=1&uid=`); in-app red X (top-right) postMessages `100x-widget:close`. Test harness: `/widget-test.html`
- **Header + profile show the PLAYER, not Vuma** (2026-10-09; Vuma Katongo stays the story character in the art, "My story" bubble and level-up copy): the player's name with "ID <userId>" under it; no name → "ID <userId>" as the title + an "Add name" button (pencil badge on the avatar on phones, pill on desktop); no id and no name → "Player" (id = SSO `bwanabet_user_id` → username → `?uid`). Names: `lib/profile/name.mjs` (`validateName` 2–16 chars, letters incl. accents, digits, space . _ -; `canRename`/`setName`/`normalizeNameState`; tests `tests/profile-name.test.mjs`); state keys `user.displayName` + `user.nameSetAtStage` (saved with the state blob). First name any time; after that ONE rename per stage-up (allowed when current stage > `nameSetAtStage`); the profile modal holds the name form (locked → "You can change your name again at Stage N+1"), the level-up modal adds "You can change your name now" for named players; nav badges are things-to-attend-to in platform green (Home = unclaimed daily reward, logged in only; Missions = missions ready to claim)
- **Missions = 4 DAILY casino missions** (2026-10-07; old daily/weekly/permanent missions parked in `parked/lib/data/missions.legacy.js`): Casino Starter 20 rounds → 50 coins, Regular 50 → 100, Pro 100 → 500, Legend 200 → 1000. ONE counter: casino rounds (slots = casino) played on bwanabet.com **today, Africa/Lusaka day (UTC+2)**. Definitions + pure logic in `lib/missions/casino.mjs` (`casinoMissionStates`, `recordClaim`), feed helpers in `lib/casino/feed.mjs` (`lusakaDay`, `validateCasinoBatch`, max-wins merge); tests `tests/casino-*.test.mjs`. Data path: CRM → **`POST /api/activity/casino-rounds`** (`Authorization: Bearer $CASINO_FEED_SECRET`, constant-time, disabled while unset; batch ≤ 1000 rows `{userId, date, rounds}`; ABSOLUTE daily totals upserted max-wins via the `upsert_casino_rounds(jsonb)` SQL function, so resends are idempotent; date within ±2 days; rate-limited) → table **`casino_activity (user_id, day, rounds, updated_at)`** (migration `lib/supabase/migrations/2026-10-07-casino-activity.sql`) → **`GET /api/missions/progress`** (identity from the SSO token like `/api/purchase`, never a client id; returns `{ day, rounds, updatedAt }`, 503 when the table is unavailable). The client (`SessionProvider.getCasinoProgress`) fetches on widget open, on every Missions-tab visit and every 60s while that tab is visible. Claims re-fetch the count, then credit client-side (medium reward animation) and record `user.casinoMissionClaims = { day, ids }` so each mission is claimable once per Lusaka day. No feed row yet → 0 rounds + "Play casino on bwanabet.com — progress updates every few minutes"; no SSO session → "Log in on bwanabet.com to track missions". `trackMission` is now only the `game_played` beacon. CRM-facing spec: `docs/integrations/crm-casino-rounds-feed.md`
- **Store (LIVE pipeline, gated on the JWT key)**: items come from remote config (CRM dashboard stocks them). Purchases are server-backed: `POST /api/purchase` (identity from the verified bwanabet JWT — NEVER client-supplied; atomic stock via `purchase_item` RPC; rate-limited) → Telegram admin-group message with a ✅ credit button (`lib/telegram/`) → `/api/telegram/webhook` (secret-verified) or the CRM Fulfillment queue credits/rejects. Rejections refund exactly-once on the player's next session (`refundedPurchaseIds`). TRUST POSTURE (user decisions 2026-07-17): production runs with `SSO_ALLOW_UNVERIFIED=true` (no JWT signing key) — accepted because purchases credit the NAMED player's bwanabet account and withdrawals lock to the registered phone number. Purchases ARE balance-enforced: `purchase_item` RPC verifies + deducts the server-held `profiles.state` coins (`kwacha`) + emeralds/rubies/diamonds atomically with the stock decrement; the client mirrors the SERVER row's charge (`paidFromPurchase`) and its absolute state save reconciles; refunds of rejected purchases return the exact currencies (`refundTotals`), once. Prices: `price_kwacha` (coins), `price_emeralds`, `price_rubies`, `price_diamonds`; items still priced in the retired `price_gems` are dropped from the catalog and refused by the RPC. **Kwacha redemptions** (Store "Redeem for kwacha": K1/K5/K10/K20/K50 coin packs + 1 Emerald → K5, 1 Ruby → K10, 1 Diamond → K20) are ordinary `store_items` rows with `redeem_currency` + `redeem_amount`, seeded by migration `lib/supabase/migrations/2026-10-07-gem-currencies.sql`; `/api/config` (`buildStoreCatalog`) and the RPC both DERIVE their price + `payout_kwacha` from the economy row, so a rate change reprices them all. Stock unlimited (NULL); `is_money` so the weekly cap applies: ONE money item per player per rolling 7 days (rejected ones don't count). Redemptions use a two-tap confirm. Telegram: "💵 Kwacha redemption #id / Credit K5 bwanabet bonus to player 123456 — paid 5,000 coins" (or "— paid 1 Emerald"). Known boundary: `/api/state` saves remain client-authoritative (a modified client can still write arbitrary balances) — server-authoritative EARNING is a separate future project. If the bwanabet JWT key ever becomes available, set it + drop the override for defense in depth

## Design Direction
- Casino/gamified aesthetic — deep indigo-plum background palette (cyan reserved for Diamond VIP tier, General Knowledge category, in-progress indicators, diamond reward text)
- Typography: Bricolage Grotesque (display) + Onest (body) + JetBrains Mono (tabular)
- Unified card system: `.card` base with `--elevated` / `--flat` / `--match` variants
- Dopamine-driven engagement: urgency cues, progress bars, streaks
- Mobile-first, responsive grid layouts
- Skill: `.claude/skills/frontend-design/SKILL.md` loaded for design quality

## Reward Animations
- `triggerReward(tier, sourceEl, rewards)` — 22 call sites across the app
- 2-layer motion budget (excludes persistent WebGL background):
  - `small` → 1 layer: floating number(s)
  - `medium` → 2 layers: floating number(s) + gold screen flash (~180ms)
  - `big` → 2 layers: fly-to-header currency trail + confetti burst
- `useReducedMotion` hook collapses every tier to a single static floating number when `prefers-reduced-motion` is set
